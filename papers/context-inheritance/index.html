Context Inheritance: A Git-Native Architecture and Pre-registered Study of Repository Context for AI Coding Agents

Pavel Kerbel · Milana Kerbel · Vitali Abramov · Liat Abramov
Metatron Research · Published October 8, 2026

Engineering knowledge should survive the session that produced it. This paper introduces the Repository Context Layer and studies when one coding agent can inherit useful context from another.

Read the published paper at ACM · Presentation & PDF slides · Open study materials

The question

A repository preserves the code a team shipped. It often loses the knowledge behind that code: the rejected approaches, constraints, and lessons from failed attempts. Can we make that knowledge a reviewed part of the repository, and can a future coding agent use it?

The Repository Context Layer

The paper describes a Git-native architecture for persistent agent context. Agents consult repository knowledge before working, execute their task, and propose context updates for human review. Context branches, merges, and rolls back with the code. Context.md supplies the discovery contract; Metatron is a reference implementation.

What the study found

The pre-registered study used SWE-bench Verified to examine context authorship, the agent reading it, and delivery. On tasks sharing relevant project constraints, an 8B local model’s code-localization accuracy increased from 21.1% to 47.2% with frontier-authored context. Its own lessons brought no improvement. We call this pattern context inheritance.

The strongest result concerns locating the right code, rather than a confirmed improvement in successful bug fixes. A frontier agent’s failure-derived lessons showed a directional resolve increase, but it did not remain significant after the reported multiple-comparison correction. On a broad random sample, no context delivery improved the frontier agent’s resolve rate.

The experiment evaluates the underlying architecture with a minimal harness. It is not an end-to-end benchmark of Metatron’s extraction or serving tools. The protocol, data, scripts, and reported deviations are public.
